# Progression presentations and endings

**Outside, Water and Castle now have independent, source-sequenced presentation controllers and indexed render helpers. Phase5 now wires them into Session/main; the integration record is `reports/PHASE-5.md`. The worker proposal below remains source-boundary documentation, not a current omission claim.** No archive program was executed, interpreted, emulated or launched. The source clock waits, skip boundaries and RNG calls were recovered statically, not measured against DOS playback.

## Integration contract

Files owned here:

- `recovered/control/celebration.mjs`: `Celebration`, three source-specific sequences, exact packet/wait/input ordering.
- `app/celebration-render.mjs`: `hydrateCelebrationResources`, `CelebrationRenderer`, `celebrationFade`.
- `recovered/control/results.mjs`: added `resultEntryEffects` and `resultNextState`, preserving existing APIs.
- `tools/control/celebration-inspect.py`: archive hash verification, byte/listing checks, complete local scene/font/actor/BAN resource binder.
- `tests/control/celebration.test.mjs`: source traces, lifecycle, resources and indexed rendering.

Regenerate from the checkout root:

```sh
python3 -B transpile/tools/control/celebration-inspect.py
```

This reads the hash-pinned ZIP, imports only the inspected, newly authored render decoder, verifies 3,177 instruction-byte records in the existing inert listing, and writes **only** ignored `assets/render/celebration/bindings.json`. It needs the existing `analysis/worlds/disassembly.txt`, regenerated by the PLAN worlds inspector. All 22 input member hashes, decoded GSO indices, raster sizes/hashes, exact BAN packet byte spans/write runs, font metrics and message resource IDs/indices remain in that ignored binder. No raw table or extracted text is tracked.

```js
const resources = hydrateCelebrationResources(localBindings);
const presentation = new Celebration({
  world: mode, character, goal: advance.state.goal, lesson: advance.state.lesson,
  endMode: advance.ending, swimFrame: survivingWaterFrame, rng: sharedRng, resources,
});
const renderer = new CelebrationRenderer(resources, character, {front, background, palette, clip, textState});
// Drain effects on entry, then after a wait is satisfied. Do not acknowledge
// a changed-low-word tick more than once for a sampled host tick.
const effects = presentation.step({input: existingByteQueue, tickReady, pointerChanged});
renderer.apply(effects);
// Resume the suspended world's tail ONLY after celebration-complete.
```

`palette` is a writable768-byte **RGB6** buffer, not the shared Renderer's string palette name. On display, integration converts components with `Math.round(value*255/63)` and presents the indexed front buffer. `apply()` returns the ordered RGB6 palette writes if the host records them.

`wait` is `wait-tick`, `wait-input`, or null. It is not an arbitrary movie-complete acknowledgement. Existing `createPendingInput()` is accepted directly. A final key is flushed, including all extended-key bytes, before completion. Finished instances are inert; a new entry needs a new instance. The shared RNG object survives entries. There is no internal timer, DOM event handler, clock sampling, save, certificate printing or progression calculation.

## Directly recovered sequencing

All offsets below are executable **FILE offsets**, not relocated memory addresses.

### Outside, `0x13e29..0x1413c`

- Load OCASTLE, splice character palette slots32..47 (`0x14a8c`), set black, copy scene, install final scene palette. Save text state and select FONT3H. Flush input before movement (`0x13f09`).
- Start `(-50,110)`, movement `(5,1)`. Test the **old** X; when `X>155`, movement becomes `(2,-3)`. Increment frame first, then modulo12, then move/draw. Exactly55 moves finish at `(186,113)`, first run frame is index1, not index0 (`0x13f0e..0x13f94`).
- One changed-low-word wait per move. Only then poll input. An early key flushes the queue and jumps to text, without removing the last actor or freeing character frames (`0x13f99..0x13fa7`). Do not invent a final centered pose.
- Full movement removes the actor and calls character-resource free (`0x13fb4..0x13fd8`). Browser resources remain immutable cached data; the free effect denotes original allocation lifetime, not permission to delete shared app assets.
- Up to ten fireworks. Poll for a pending key **before** each draw. One shared `rand()` call selects FIR1 for odd low bit, FIR2 for even low bit. It is not `boundedRandom(2)`. FIR1 has26 packets, FIR2 has25 (`0x13fe1..0x14021`).
- Each movie is one pass, no ANI argument, callback `0x14725` gives **two** changed-tick waits per packet. These callers pass repeat=0, so the shared movie player's inner key check is disabled. A key arriving during a firework cannot interrupt it; it skips later fireworks/draws at the next outer poll. No bonus sound callback applies here.
- Text: resource7010 at column3,row2. Goal>=10 displays7050 at3,5 and certificate instructions4300..4302 at3,8..10. Otherwise6100/6101 at3,5..6 include the new goal and lesson. Prompt50420 is13,20. Flush, await keyboard or available mouse-button change, flush, pop text state, free OCASTLE (`0x14023..0x14134`). **No previous world image is restored.** The caller saves, clears its screen, cleans resources, resets audio, then enters results.

### Water, `0x17aa3..0x17e02`

- Load WCAS0001 and patch character palette32..47. Push text state/select FONT3H, set black, copy scene. Draw6010 at3,2 and6011 at3,3 **while the palette is still black**, then fade black to the scene palette (`0x17afc..0x17bb4`).
- Start `(-45,110)`. Preserve incoming swim-frame index DS:4ff8. Add3 to X. Increment Y only when **new** X<65 and old Y<140. Every second update advances/wraps the six swim frames. Set clip `(0,0,105,199)`, draw using old/current frame and coordinates, then reset clip to full screen (`0x17bd9..0x17c84`).
- One changed-tick wait per update, no key polling. Stop when X>120: exactly56 moves, `(123,140)`. For incoming frame5, outgoing frame3.
- Flush input, play WCAS.BAN once,48 packets, two waits per packet, no ANI, no RNG and no inner key skip (`0x17c95..0x17cb5`).
- Goal>=30 displays6050 plus certificate instructions; otherwise6100/6101. Prompt50420 at13,20. Flush, wait for keyboard/available mouse-button change, flush (`0x17cb8..0x17d7f`). This is not skippable swimming or a replacement happy animation.
- The loaded-object flag at `0x17d87` gates cleanup. A successfully loaded WCAS object has flag+3 set (`0x1c765`). Clear framebuffer bit7, fade scene palette to black in12 unwaited steps, clear the visible screen to0 through `0x1ac9a`, free WCAS0001, pop text state (`0x17d8e..0x17df8`). The framebuffer clear is **not resource cleanup** and is rendered here. Neither the old Water image nor old actor positions are restored.

### Castle, `0xdf46..0xe127`

- Every mode loads the same ENDF.CRX, immediately sets black/copies it, saves text state/selects FONT5H. Unlike the other two paths, there is **no character palette splice**.
- Every mode draws7010 at4,2;6100(new goal) at4,4;6101(new lesson) at4,5. Existing earlier prose suggesting that bits1/2 individually select those texts was wrong. The routine only tests **bit4**. Bit4 additionally draws4300..4302 at4,20..22 (`0xdff7..0xe087`).
- Fade black to ENDF in12 unwaited steps; prompt50420 at13,25. Wait exactly18 changed ticks with no key check, then flush. Early input is discarded, not an immediate return (`0xe088..0xe0c5`).
- Modes1/2 await keyboard/available mouse-button change with callback `0x147f2`, then flush, pop text state and free ENDF. No run, jump, happy pose or movie is inserted.
- Mode4 plays **ENDF.BAN repeatedly until a key**,40 packets per pass. Each packet draws, waits twice through `0x14725`, then checks keys. A skip flushes; the routine flushes again at `0xe106`. A completed pass resets packet index/pointer to0 but **does not restore the starting scene pixels** (`0x81df..0x838e`). Pointer changes do not interrupt ENDF playback. No RNG is consumed.
- First Castle completion is written at `0xdacb`, **after** the ending returns, then saved at `0xdadc`. Later Castle graduation returns mode1 rather than mode4. No old Castle gameplay scene is restored before results.

### Progression, results and certificates

- Reuse `progression` from `flow.mjs`. Outside new goal=result+2 completes only for strict **>10**; Water result+5 completes only for strict **>30**. Both clamp to their cap only after passing that strict test. A goal exactly10/30 already selects graduation text and a higher-world Next route, but does **not** set completion/certificate eligibility (`0x13d82..0x13da3`, `0x17e6a..0x17e8b`).
- Castle result+5 is uncapped. At>=45 choose4 if not yet completed, otherwise1; below45 choose2. Advancing a lesson below6 chooses1 (`0xda87..0xdadc`). Signed16 arithmetic remains in the existing helper.
- Results draws stats operation210 before requesting congrats/toobad. Compare result WPM with **previousGoal**, not raised goal. Gates: suppression clear, profile present, mode!=4, Outside goal<=10, Water goal<=30. Request congrats for >=previousGoal, otherwise toobad. Then reset suppression, flush, initialize pointer `(78,184)`, clear Next (`0x16598..0x16627`). Demo instead clears Next and flushes, bypassing results **without** resetting suppression (`0x16507..0x16519`).
- The speech wrappers `0x14f74`/`0x14f90` request named resources through `0x18d22`. No playback duration, stop, added delay or synthesized voice is invented. Device/option handling remains Phase6.
- Certificate arrays are separate bytes: completed DS:50ce..50d0, printed50d1..50d3, pending50d4..50d6 (student offsets38..40,41..43,44..46). Queue only when profile present, completed, not printed and not already pending (`0x103be..0x103f7`). It does not mutate printed flags.
- Queue calls for worlds0,1,2 occur in **Next routing**, then profile save (`0x10457..0x10475`), after the world's presentation/save/results path. Do not queue on entering a celebration or call progression twice. The automatic Next wrapper clears its request before routing (`0x11b92..0x11ba3`).
- The manual certificate screen `0xaaf9` uses CERTIF.CRX (SHA256 `03fd9c5f92756d72b8013a7d60fdc5ba691b01d594b9b08e80d4d221370ae970`, name bytes FILE `0x20ddd`) and allows selection among completed worlds. Its document path `0xb069` constructs a real **80-column by60-row text document**, not a new browser certificate: allocate60 buffers of81 bytes, fill80 spaces and NUL (`0xa8f0..0xa974`), draw a `*` border (`0xb001..0xb068`), add rows centered around column40 using4200..4205, student name and world-name lookup (`0xaf16..0xb000`), then output60 formatted rows through `0xa9a3 ->0x14a32` until an error. The latter writes each byte through C stdio `0x65ce` using the source FILE object DS:3a60. Printer/device success, exact external device output and printed-flag mutation are **not claimed recovered here**. No browser print/export or invented certificate raster is implemented.

## Browser adaptations and limits

- Recovered waits are changes of the BIOS tick **low word** (`0x192a2`), not milliseconds or elapsed-wall catch-up. The host supplies one acknowledgement for each observed change. Browser scheduling, focus and typematic remain host differences.
- The initial Outside previous-raster erase is omitted because DOS resets its position toX=-50. Direct archive decoding gives maximum X-origin+width40 for WALKING and37 for IDLE, so the old raster ends off-screen there. No incoming run-frame index is invented; subsequent previous/current rasters are preserved exactly. This extra bound check read IDLE.GCO SHA256 `76d661e591f6f7ad531a12e3fa7d07e88e7ffa14acf3153154cd8609add8c45f` and IDLE.GCK SHA256 `9e533e049d4646f7daf29907ecacee3eb729fddc2dce9bd146f752d472ed6086` as data using the inspected existing decoder.
- Native palette fades issue initial palette,12 integer interpolation writes and final palette; these call sites pass wait=0 (`0x14bb4..0x14d0a`). `celebrationFade` returns all14 palette writes exactly. A browser may display only the final palette in one callback; that is an explicit display adaptation, not a recovered fade duration. Entry palette-black is immediate, not an invented transition.
- Loaded resources remain cached immutable JavaScript data rather than emulating DOS allocation/free. The selected path fails visibly on missing scene/movie/actor/font/message data before RNG or input changes. Hydration rejects malformed dimensions and out-of-screen BAN writes; it does not substitute art or skip missing frames.
- All-three-character controller/resource/palette paths are tested. No original-machine differential test, integrated browser test, audible output, printer transport or exact hardware cadence is claimed. Session/main/build-data integration is now implemented, including clock, profile save and renderer ownership; see the Phase5 report for checks and remaining host gaps.
