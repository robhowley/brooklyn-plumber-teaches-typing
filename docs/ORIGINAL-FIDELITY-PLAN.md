# Original-fidelity adoption plan

Adopt the recovered scoring, progression and lesson material, and preserve the original screen flow with suitable archive assets and only the adaptations needed for browser use and accessibility.

**Status, 2026-11-10:** Phases 1–6 automated implementation and verification are complete. The latest integration adds fixed outdoor background layers, unconditional access to all four activities, and semantic PREFS Done/Cancel controls. Source-backed Node tests passed **63/63** and the full production-browser suite passed **105/105 with no skips**; the local preview was restarted and every served build file matched `dist/`. Commands and screenshot/HTTP evidence are in [Validation](VALIDATION.md). Human review was not performed. G1–G4 remain historically open; approved browser choices apply and all early deaths remain disabled. Historical facts come from [Executable research](EXECUTABLE-RESEARCH.md); earlier manual evidence is in [References](../references/README.md). Automated completion is not release approval or human/DOS runtime validation.

The recovered and v1 course shapes are not equivalent, so the archived old position does not map into the new course. New schema validation must support ruleset IDs, corpus version and immutable pending-result snapshots.

## Adopted browser gameplay contract (delegated choices; historical gates remain open)

### Scoring and input

- Count attempts as correct plus incorrect printable keys. Wrong characters increase errors and leave the current target/cursor in place. Spaces count. A buffered outdoor key counts once when accepted at contact, not once on buffering and again on contact.
- Replace `correct × 12 / elapsedSeconds` with `floor(max(0, correct − errors) × 182 / accumulatedTicks)`; nonpositive ticks yield zero. Compute accuracy as `floor(100 × correct / attempts)` for positive attempts, otherwise zero. Use the same values for HUD, results, eligibility and progression.
- The constant 182, subtraction, clamp and integer calculation are confirmed at `0x15c8f–0x15d74`. Six net characters per minute-word follows only if the tick accumulator advances at approximately 18.2 Hz. It is an inference, not a substitute formula asserted as exact DOS timing.
- **G1 remains historically open. D2 selects** `ticks = floor(activeSeconds × 182 / 10)` from one cumulative active clock, not flooring each frame delta. Display elapsed seconds from that clock; document the difference from original `floor(ticks × 10 / 182)` reporting. Keep duration expiry in active seconds. This is an approved browser approximation, not exact reproduction.
- Use safe JavaScript counts, not DOS overflow/wraparound. Reject invalid numeric state; do not emulate finite-width overflow. This and the zero-attempt pass guard are retained browser safety rules, not recovered DOS facts.
- Outdoors, convert ASCII `a–z` input to uppercase before comparison against reviewed uppercase ASCII letter targets. Do not apply locale/Unicode uppercasing or change punctuation. Prove how lowercase corpus targets become displayed targets at text gate G3; the executable establishes input folding, not arbitrary target rewriting.
- Water, castle and practice retain exact case/punctuation until their handlers establish otherwise. Ignore repeat, composition, modifiers, Backspace, Alt and Ctrl/Meta shortcuts as today. Unsupported non-ASCII input cannot become an equivalent ASCII answer through normalization.
- Retain continuous active-time scrolling, starred ordered targets, one-key outdoor contact buffering, returning missed targets without penalties, and custom-goal travel speed scaling. Contact timing was not recovered; these remain explicit user-requested browser mechanics, not DOS claims.
- Reduced motion keeps stationary, immediately typable targets. Finger hints must reflect the accepted outdoor case rule without requiring Shift unnecessarily; other modes retain opposite-Shift guidance.

### Modes, duration, goals and course advancement

- Keep four distinct activities: outdoor object keys; underwater words; castle sentences/hazards; plain practice with performance faces. Default active limits are 120/300/300/600 seconds. Keep user overrides, including short seconds-based tests; historical configured values multiply minutes by 60.
- Start guided students at goal 5, lesson 1. Map UI lessons 1–6 to internal groups 0–5: home row, add top, add bottom, add numbers, add symbols, all keyboard. Exact historical character membership remains subject to G3, not inferred solely from filenames.
- Route the guided course by goal: below 10 outdoors, 10 through 29 underwater, and 30 or above to castle. Separately, make all four activities available at every configured goal for new and existing students. This explicit product decision supersedes the original-DOS-inspired browser access gates without changing the goal, stored course position, or earned records. An off-course result cannot advance the guided course. Practice remains course-isolated.
- On an eligible result with lesson below 6, Next increments the lesson and retains goal. On eligible lesson 6 results, Next assigns **achieved integer WPM +2 capped at 10 outdoors**, **achieved WPM +5 capped at 30 underwater**, or **achieved WPM +5 in castle**. This replaces uniform old-goal +5.
- Route using the new goal. When changing into water or castle, reset to lesson 1. Within the same world, retain lesson 6 after a speed increase. This replaces retaining All Keyboard across world transitions; do not invent a reset after every speed increase.
- Exact original eligibility flags and advancement-versus-Next timing are not fully traced; **G2 remains historically open**. D3 selects the conservative browser fallback: timeout, attempts >0, integer WPM ≥goal, accuracy ≥90%, and no failure flag establish eligibility. Reaching live goal never succeeds early. The 90%/attempt guard is not claimed as original behavior.
- Under that fallback, `recordResult` stores an immutable pending transition containing achieved WPM, source course position, ruleset and result identity. It does not move the course. Explicit Next from results or menu commits once, saves, and returns to the menu, never auto-starting another lesson.
- Repeated Next, repeated result delivery, reload, or stale results cannot advance twice. A failed/retried attempt cannot reduce goal/group or erase a previously earned pending transition. Once pending, retain its first successful result rather than replacing its achieved speed on a later retry. Custom/off-course results cannot create or replace it.
- Keep world certificates on committed outdoor→water and water→castle advances, and graduation at a successful guided all-keyboard castle attempt with goal 50. This is D3 browser policy; G2's historical certificate eligibility remains open.
- Achieved-speed increments can skip goal 50. D3 adopts the browser safeguard: if an ungraduated castle transition would exceed 50, offer the 50-WPM graduation assessment instead, retaining lesson 6. This is not the recovered uncapped castle assignment. Test both exact 50 and overshoot routes.
- Graduation records once on the eligible 50-WPM assessment, clears pending, and keeps custom/practice available. The `new goal ≥45` branch at `0xdaad` does **not** replace graduation with 45; its ENDF/certificate meaning remains gated.

### Failures, pauses and outcomes

- D3 retains the universal **90% timeout rule as an explicitly labeled conservative browser fallback**, not a historical finding. Do not replace it with the scoped below-70 castle evidence; that is not evidence that 70% universally passes.
- The confirmed castle predicate **attempts ≥50 AND integer accuracy <70 only within handler operation 2** remains inactive: G4 has not established which browser chamber/state corresponds to that handler or when it runs. D7 keeps all early deaths disabled; do not guess a mapping or apply this predicate globally.
- Water and castle have inactivity failure paths. Castle compares last-input interval **>20**, not ≥20. **G4** must determine units, clock conversion/rollover, handler cadence, qualifying key resets (correct, wrong, ignored keys), initial grace, applicable scene states and interaction with pipe transit. Water's threshold must be traced independently.
- The retained browser adaptation runs gameplay timing on active time only, even if DOS used wall-clock helpers. Escape, blur/hidden tab and pipe transit pause both input and every gameplay clock; explicit resume resets the wall-clock baseline and never charges background time.
- Keep every early death disabled under D7. Retain nonterminal hazard feedback and timeout-only ending. Do not turn the current water chase, 3px/s quicksand sinking, 12px/s recovery or every-40-key pipe switch into historical death thresholds.
- For a resolved early failure: freeze counters/active time at failure, clear buffered input, mark a terminal reason, show a brief skippable effect using suitable original assets, with minimal adaptation only where needed (immediate under reduced motion), then blackboard results. The effect cannot add time, accept keys, grant success or revive the attempt.
- Retry starts a fresh attempt with the same selected options and deterministic initial text sequence. Menu preserves progress. Next stays locked unless an earlier valid pending pass exists; failure itself never unlocks it. D7 requires chronological event handling, buffered contact due at timeout before timeout, and no new key at or after expiry. Results expose terminal reason and actual active elapsed time. No lives or automatic restart.
- Results show actual active elapsed time, not configured duration after early failure; retain separate configured limit. Announce timeout/pass, insufficient speed/accuracy, or the specific resolved failure reason. Never infer a separate victory screen from the graduation costume or audio filename.

## Lesson corpus contract

The import is data work, not permission to run original software. Preserve the local raw source and publish only reviewed learner strings plus provenance metadata. Selected, reviewed static archive art may also be packaged under the policy below; never run or ship an EXE, loader, driver, installer, archive script or other unreviewed executable material.

1. Inventory all **15 files, 24,090 bytes, 136 records** (78 LETTERS, 41 WORDS, 17 SENTENC). Preserve member SHA-256, exact byte spans, record hashes, case, spaces, CRLF, tilde, backtick and terminal `0x1a` in reference evidence. Do not normalize the raw layer.
2. Build a separate parsed representation with source member/record/span and explicit control tokens. Tilde-delimited extraction is known; whether tilde/backtick/CRLF/end-marker produce learner input, boundaries or transformations is not. G3 remains historically open; D5 authorizes the scoped browser contract, but fixtures must establish each byte's treatment before runtime wiring.
3. Trace selection of H/T/B/N/S files, per-mode LETTERS/WORDS/SENTENC usage, lesson index, record order, filtering and all-keyboard selection. No historical sixth-prefix/all-keyboard file is established. D5 defines H→T→B→N→S as a deterministic browser schedule; do not call it original selection.
4. Every HWORDS record and five of seven TWORDS records exceed inferred key groups. Neither blanket character filtering nor presenting whole records unchanged is justified. Under D5, Phase 2 must classify source records against corrected key membership and use a labeled generated fallback only where required keys are unavailable; do not strand learners or silently filter text.
5. Under D5, specify a deterministic learner sequence and cursor per mode/group/corpus version. Store record index and character position independently of raw byte offsets; only correct acceptance advances it. Define record separators, exhaustion/repeat and retry start in fixtures. Preserve recovered order where proven; source-order replay and retry are browser choices, not recovered randomness.
6. Use the same reviewed sequence contract for guided and custom matching groups. Under D5, practice can use selected lesson text without advancing course; the original practice-record selection remains historically unproved. A custom mode/group combination uses a visibly labeled generated fallback only where reviewed historical coverage is incompatible or scored-wrap semantics remain open.
7. Keep corpus ASCII exact. Do not smart-quote, case-fold, collapse spaces, modernize wording or silently map Unicode lookalikes. Display control/space hints separately from scored characters. Escape DOM text; review every shipped learner string and reject unhandled control bytes.
8. Preserve historical Washington/Pluto claims and war passages in the raw/reference corpus. D4 selects verbatim learner text only after full review, with a visible notice naming outdated claims and war, slavery, assassination and disaster content, plus a clear generated-practice alternative; do not silently censor or modernize and still call the result original.
9. Under D5, generated text is only a bounded, visibly labeled fallback for records/groups with incompatible required keys or practice scored-wrap gaps, plus the explicit alternative. Phase 2 must publish the exact mode/group/record coverage matrix. Historical-corpus completion is not claimed for fallback combinations.

## Validation and release evidence

Use `structured_return` for tests/builds, after reading its skill for compact parser/reporter flags. The checklist below specifies acceptance scope; executed checks are recorded separately in [Validation](VALIDATION.md). Human review must remain explicitly not performed until a real report exists.

- **Scoring boundaries:** zero/nonpositive ticks; zero attempts; errors greater than/equal to correct; one tick; integer WPM/accuracy truncation; elapsed tick boundaries; goal equality; large safe counts; invalid numeric state; one large time step versus many frames. Compare literal 182/ticks vectors, not only a six-character approximation.
- **Input/text:** upper/lower ASCII outdoors, exact case elsewhere, punctuation/spaces, modifier/repeat/composition/shortcuts, unsupported Unicode; wrong key leaves cursor; contact buffer accepted once; misses return; all corpus file/record hashes and counts; CRLF/tilde/backtick/EOF fixtures; H/T anomalies, all-keyboard mapping, deterministic repeat/retry, escaped historical text and fallback disclosure.
- **Course:** six stages, +2/+5 from achieved rather than goal, outdoor cap10/water cap30, route boundaries 9/10/29/30, world-entry lesson1, within-world lesson6 retention, repeated Next/result/reload, immutable pending award, failed retry preservation, custom/practice isolation, 50 assessment and overshoot. Replace the current fixed “15 passes graduate” expectation with routes determined by actual achieved speeds.
- **Failures/clocks:** attempts49/50, integer accuracy69/70, handler outside/inside scope, interval exactly20/>20 only after units resolved, water's own threshold, qualifying key resets and ignored keys, pause/blur/hidden/pipe freezes, resume baseline, failure versus timeout/contact tie ordering, early-failure elapsed time and no revival. Define tie ordering in Phase 1 test vectors, not incidental frame order.
- **Storage:** every approved legacy conversion choice; odd integer goals and reset groups; legacy results/certificates retained and separated; duplicate/stale pending results; malformed JSON/unknown versions; corrupt students/current selection; unavailable/quota storage; interrupted conversion retains recoverable old save; cross-reload student selection and settings.
- **Rendering and screens:** all screen families with actual DOM overlays, all three characters, read-only renderer, palette/reference comparison, title teardown/fallback, face states, outdoor actions and water/castle hazard feedback. Check reduced motion, visible focus, contrast, zoom/narrow layout, keyboard shortcuts outside text fields, accessible announcements and print/download contents.
- **Production browser play:** rebuild then test `dist/` over HTTP using `playwright.config.js`, not only dev. Drive actual keys/actions through all four modes to pass/fail/results/retry/menu, profile creation/loading/editing, times/help, report and certificates. Cover reload before/after pending Next and migration, plus early failure only where enabled.
- **Entire guided course:** automate from new student through all lesson stages/world transitions to 50-WPM graduation, reload at boundaries, verify certificates once and practice afterward. Use controlled achievable WPM fixtures, not huge one-second bursts that unintentionally skip proposed goals. Cover normal-motion contact and reduced-motion paths separately.
- **Evidence:** preserve test JSON/JUnit summary, exact commands/build revision, ruleset/corpus hashes, browser version, screenshots for every screen/mode/result and course milestone, and failure traces under a named fidelity-validation artifact directory. Record authored fake clocks/Playwright automation separately from human keyboard play. Human review must play each mode and inspect flow/readability; neither is original DOS runtime validation.
- **Bundle audit/documentation:** no EXE, driver, installer, archive scripts, DOS decoder or unreviewed executable/resource material. Include only reviewed learner strings and selected static assets under the approved policy; no external runtime assets. Update limitations with unresolved gates and retained browser rules. Do not call historical fidelity complete while generated coverage, timing or eligibility fallbacks remain undisclosed.
