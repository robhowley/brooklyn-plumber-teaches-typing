## Input, student state and unsupported routes

- Outside/Practice retain one pending ASCII/DOS-normalized key per update; additional DOM events before consumption are dropped. Water uses `createPendingInput()` with separate pending/consume/flush calls, drains bursts in source order, and suppresses actor/RNG updates while input remains. Its unbounded FIFO and DOM delivery are host adaptations, not BIOS queue capacity or typematic emulation. BIOS queue size/typematic is not claimed. Modifiers, composition and non-ASCII input are ignored. `createPendingInput()` separately tests raw-byte pending/consume/flush and extended prefixes; Water converts normalized extended keys back into prefix/scan bytes at ingress; no DOS queue capacity is claimed.
- Guest `Player` has profilePresent=false and never saves. It is not Demo and receives no synthetic input.
- Canvas student controls use the source name/numeric editors, source focus/hit rectangles and chooser. Names accept uppercase letters/digits, max8. Goal clamps5..150, durations1..60 in their four source fields. The separate native fallback form still uses browser validation/selection and accepts printable ASCII names; it is not an original-widget claim.
- New clears all260 bytes before prompting, including cancellation. Duplicate New names load existing records. Rename Escape cancels before deletion; accepted rename deletes OLD then saves NEW, without confirmation. Whole-dialog Escape saves current edits. Chooser D means Done/load, not Delete; C/Escape has no storage effects.
- Filename lookup/save matching is case-insensitive to model DOS path intent, not a recovered directory implementation. Save reuses an existing host key and changes only the intended record/current pointer. No migration, namespace change or bulk rewriting occurs. Source New cancellation can leave zero working bytes; the next source student service normalizes its owned group/accuracy/character fields.
- Storage uses only `mtt-static-translation.students.v1`. Corrupt/unavailable reads produce a persistent visible warning and an in-memory guest; write failures leave the student in memory and show the same warning. DOS file errors/carryon/device transport are not reproduced. Rename's ordered delete/save intents run through the existing localStorage object; failed writes remain explicitly memory-only, not a simulated DOS error dialog.
- Practice Next stays mode4 without advancement. Outside progression occurs before results; early exit withholds advancement; Next never advances a second time. Next can enter Castle at goal30. It does not invent a postcompletion route to Practice.
- Original right-side and dropdown hit regions, accelerators, navigation and profile gates are used. The controller API preserves keyboard-first menu/PREFS and pointer-first duration/chooser dispatch. Browser DOM events still arrive separately; native event timing is not a DOS polling oracle. Main/PREFS require a fresh left press, chooser also samples held-left level on host ticks. No right-click action is substituted.
- Report/About consume their closing key or button change, Keyboard keeps F1 open and consumes one other key, Help owns its paging keys. Each saves/restores caller raster/palette/pointer and returns to menu or results, never a newly started lesson. No modal key reaches lesson input. Report/About button changes are transported as a fresh browser press (any button), not driver release polling. Keyboard uses pending keys only.
- Quit is an explicit browser limitation, not tab closure. Explicit Demo is implemented. Printing remains disabled. Four exact VOC clips now play through explicit browser transport;58 unsupported resources stay silent. Alt-X uses KWD>=10 (false without a browser environment), not an audio bit; menu Quit is unconditional, notice only.

## Audio transport

- `tools/audio/decode.py` verifies archive/EXE/CNF/member hashes and decodes four VOC clips to unchanged unsigned8 mono samples. The bundle carries exact bytes and the supplied speech3, music/effects4, options7 configuration.
- `SourceAudio` owns option bits, source request/stop order and blocking tokens. Browser transport availability is explicitly supplied, not a DOS device-initialization claim. Unsupported music/effect handles model request order only, never audible output or invented durations.
- `BrowserAudio` converts `(byte-128)/128` into real AudioBuffers at nominal1,000,000/56 Hz. Browser sample-rate representation, resampling, latency and DAC output are host adaptations. No oscillator, speech synthesis, sound driver or fallback clip is used.
- VOC input is suppressed/drained through completion. Source execution, RNG and the next source pump do not advance meanwhile; an already-running timer is not paused to exclude speech. Blur stops active PCM, acknowledges omission and applies the existing host focus timer pause; wall inactivity still continues. Storage errors do not own audio completion.
- Source M/S/G toggle bits1/2/4. Only M immediately starts/stops music2; S/G affect future gates and effects1/11 bypass S. Browser mute is a separate labeled control. Water/Practice finger prompts call graphics service1101/1103, never speech; their graphics remain missing.
- See [AUDIO](analysis/audio/AUDIO.md), [HOST-GAPS](analysis/control/HOST-GAPS.md) and [PHASE-6](reports/PHASE-6.md). Music/effect synthesis, RS, original mouse raster, Practice input/finger callbacks, certificate selector/document and intermediate palettes remain recoverable work, not completed source components.

## Rendering

`app/render.mjs` owns browser drawing. It imports `blitSprite`, `spriteRect`, `clipRect`, `drawGround`, `characterFrame` and `updateSprite` directly.

- **Indexed scene:** one320x200 buffer, converted to RGB8 only at presentation. Every sprite uses additive signed origins and transparent raw index0. Palette255 remains visible. There is no generic missing-image fallback.
- **Outside palette:** decoded final OUTSIDE palette with character slots32..47 and turtle slots48..63. No per-sprite preview palette is used. Background stays fixed; the exact20x16 executable tile at FILE0x1f582 occupies rows140..155 with old-scroll phase.
- **Idle:** all145 decoded GCO resources use the recovered schedules and names, without resizing or substituting a walking frame. Signed-distance overflow is not repaired with a fabricated wrap; unsupported frame state stops visibly.
- **Outside/Practice redraw:** full-scene redraw is deliberately a host adaptation, not an assertion that all original dirty-rectangle interactions are reproduced. Ordinary layers are drawn from post-update state rather than capturing every intermediate DOS screen write.
- **Bonus:** tested Python BAN decoder builds each persistent background from OUTSKY. Browser draws the matching ANI raster with recovered signed coordinates/origins and compositor. MOUT/LOUT/POUT play through this Outside path; matching frame count/order and outdoor callback cadence are proven. Bonus fades and synthesized sound remain absent; source sound7 requests use the decoded one-based callback tables. Phase5 adds the separate source progression presentations, not all decorative animations.
- **Practice:** original PRACTICE.CRX/GSO faces at logical142,21; source rows at30,96+10*row,32 columns, eight-pixel advances. Target row uses font foreground index0; typed prefix uses1. A static blue cursor still substitutes for Practice's blinking-input callback. Its numeric HUD now uses source operation200, separate from the input cursor.
- **Fonts:** real FONT3H, FONT5H, FONT7H and FONT9H rasters. Startup loads FONT5H into DS:4fc4 (FILE0x1262c..0x12639), FONT7H into DS:4fb5 (0x1263e..0x1264c); glyph-pointer field+b proves Outside DS:4fc0 and codes32..127 map to FONT7H indices0..95 (REENTRY). Decoded fonts stay in the resource cache, with no per-entry font state object. FILE0x1a7ba loads that field and0x1a86e..0x1a87e maps glyph indices through DS:2e0c. Practice writes mapping[0]=15 and mapping[1]=0 (target) or1 (input) at0xb2f0..0xb303. Black/purple palette0 must remain visible after font recoloring, unlike raw sprite zero transparency. Full text-engine control codes and all activity/reentry font state are not reproduced.
- **Menu:** original background and FONT5H; welcome slot88 treatment remains untraced, so visible palette12 is an isolated host substitution. Host mouse cursor replaces DOS mouse imagery. Original dropdown/text-field/chooser fonts and colors are indexed; report/help/HUD/results use source formats and positions. Welcome color and mouse imagery remain separate gaps.

No original code, driver or script runs. The previous `src/` app is removed, not imported. Translated storage keeps `mtt-static-translation.students.v1` unchanged. Legacy `typing-kingdom-v1` / `typing-kingdom-v2` keys are untouched and not automatically imported. Original-derived resources and numerical evidence remain untracked and not MIT. Only the required runtime allowlist may be publicly deployed, per [NOTICE](NOTICE); see [promotion checks](reports/PROMOTION.md).

## Water integration and remaining work

Water uses the imported controller and draw-time effects, not a fixed-rate actor approximation. `Session.stepWaterHost` drains pending source iterations, acknowledges only changed low ticks (shared with Outside wait observations), and never catches up missed ticks. The final timer stop follows the final wait. Bonus packets execute immediately then wait twice on distinct tick observations; pending input is flushed on return. Water progression suspends for56 swim updates and48 movie packets with no skip polling, then a final input wait/flush. Its exact unwaited palette writes are applied; synthesized audio and intermediate gameplay fades remain unsupported. Ready completes before music3 and last-input sampling, but its elapsed time counts because the lesson timer has already started.

Water dirty drawing preserves the swimmer phase before pursuer updates, selected pursuer resource, newly allocated bubble previous rectangles, and mode3 bonus erasure. FONT9H draws the prompt at(0,47); FONT7H stamps bonus punctuation. Character slots32..47 and BITER slots48..63 splice the palette. The process-retained wave counter drives twenty16×14 tiles at y65 from FILE0x1f6c6, per0x9cab..0x9d3f; zeros restore the scene. All three56-packet movies use actual BAN writes, not background diffs, and restore their background exactly. Water's FONT3H numeric HUD paints only on its source `stats` effect, using that draw-time snapshot, not on every bonus packet.

Castle uses the full source controller and ordered draw snapshots, including the2000-word queue,500-byte sentence bound, FONT9H metadata, rockface stages, pipe comparisons with a fresh RNG draw each time, sand entry/active/exit and repeated scene cycle. Operation2 alone checks typing/failure and refreshes scores; operation3 consumes one pending key but skips ordinary scoring/failure/statistics refresh. Every source wait needs a changed low tick, with no catchup. Postwait clip/Ready effects stay behind that wait. FIFO capacity and DOM delivery remain browser adaptations.

The indexed renderer preserves all40 strips, transition scratch rows and shifted-background bias; oldX is captured before subtracting8. Stationary clean rocks emit no compositor call, avoiding foreground erasure. Queue text snapshots do not read a later queue state. Clips are inclusive; text reads the normalized, unshifted background. All three52-packet bonus movies carry actual BAN writes, including unchanged values/literal zero, not frame differences. ANI dirty erasure follows those writes. Sand borrows scene0 for its movie and restores scene2; rockfaces retain the postmovie background. Bonus return resets last-input time, resumes the source timer, flushes input and marks rocks dirty. Separate rock/sand observed-second clocks survive cross-world reentry.

`Session.acknowledgeCastleEnding` rejects calls until the real ending controller completes. ENDF modes1/2 wait for input after18 mandatory ticks; mode4 repeats its movie until a key. The third completed byte is set after return, then deferred save/results proceed. Castle operation200 now carries an immutable statistics snapshot and paints only at that source event; operation3 and bonus packets do not invent HUD refreshes. Both worlds have source numeric layout. Ready holds the first operation tail before music4 and further controller stepping. Exact PCM or a visible omission releases it; synthesis/intermediate fades remain unsupported, so this is not full presentation equivalence. Builder additions reuse understood decoders and stay in ignored local app data. Source/member hashes and bounds: [Castle controller](analysis/worlds/CASTLE-CONTROLLER.md), [presentation](analysis/render/CASTLE.md) and [Phase3](reports/PHASE-3.md).

Phase5 startup/menu idle/Demo and celebrations are driven by source controllers, not resource availability alone. Result speech requests are ordered after stats and before suppression reset/input flush. Audio requests use SourceAudio decisions and explicit Session continuations, not delayed replay of final effect batches. BrowserAudio settles missing/locked/denied/muted/suspended/blurred playback as a visible omission with no guessed duration or later replay. A trusted gesture unlocks only future requests. DOS TZ/DST parsing remains unsupported. Original student cell inversion uses4/2 changed-low-tick waits (`0x1b0de..0x1b0ea`, `0x1ae93..0x1aef0`, `0x192a2`), sharing the retained wait observation with activities. No catchup occurs after a stalled host callback; blur pauses this host scheduler. Full original mouse raster drawing and Practice blink remain unsupported. Short help is bounded at top0 instead of reproducing the source's negative-index bug. Runtime/render worker reports contain newer recovery than the historical research handoffs; this document describes current app use.

Startup/menu/celebration waits acknowledge one observed change of the BIOS low-word sample, never elapsed-tick catchup. The host converts `performance.now()` at18.2Hz; native loader/DAC/CPU cadence is unknown. Focus loss freezes startup/celebration stepping and flushes pending keys; resume replaces the prior host wait sample without crediting the gap. `rebaseHostClock(old,new)` explicitly shifts menu elapsed timestamps and resets the wait observation when replacing a host clock. Unwaited fades preserve14 ordered RGB6 writes per fade but may show only the last palette in one browser callback. Cached resources are not freed like DOS allocations. Explicit Demo uses the shared FIFO even for Outside/Practice, preserving source overwrite/defer rules; this is not a generic auto-typer. Pending certificate flags are queued only by Next before save; printed flags, printer output and browser quit remain untouched.

`window.translationSnapshot()` returns copies for browser verification, never mutation commands. Tests use explicit supplied clocks in Node and Playwright host clock control. They prove authored integration, not a comparison with an executed original. See [Phase 1 integration report](reports/PHASE-1.md); [earlier integration](reports/INTEGRATION.md) is historical.
